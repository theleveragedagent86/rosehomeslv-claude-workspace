#### Hey, in this video, you're gonna learn:

🎮 How the Hermes Command Deck works — using /steer to redirect a running task, /queue (Q) to stack sequential follow-up tasks, /stop to kill background processes, and /model to switch models mid-session without restarting

🧠 How the /learn command turns any completed workflow or GitHub repo into a reusable Hermes skill — saved to long-term memory and applied automatically on future relevant tasks

📋 How Completion Contracts (/goal) work — assigning Hermes a goal with three parameters (verify, constraints, boundaries) and a 20-turn judge loop that keeps it working until the contract is fulfilled

🤖 How to run Ministry of Agents (MOA) inside Hermes — sending one question to three models simultaneously (e.g. Fable 5, Opus 4.8, Grok) via /MOA in Telegram and getting a synthesized answer that covers each model's blind spots

⚡ How parallelized sub-agents work in Hermes — spinning up 3 concurrent sub-agents to attack the same task from different angles simultaneously, cutting research time from 3 minutes to 15 seconds and cost by 49x

🌅 How Hermes proactivity works — combining a home channel (Telegram), a /blueprint schedule (cron in plain English), and /suggestions to have Hermes propose its own automations based on your conversation history

🔄 How the Curator self-improvement system works — a 7-day cycle that grades, merges, and prunes Hermes skills automatically with zero token cost, keeping the skill library lean and current

🖥️ When to use Hermes vs. Claude Code — Hermes as the always-on personal assistant for on-the-go tasks and ongoing agent work; Claude Code as the desktop build environment for deep construction sessions

#### In this video, I cover:

You'll start with the Hermes Command Deck — a set of slash commands most users don't know exist — covering /steer (redirect a live task without interrupting it), /queue (stack follow-up tasks for Hermes to tackle in sequence), /stop (kill all background processes), and /model (swap the active model on the fly).

You'll then learn the /learn command: use it retroactively after a successful workflow to commit it to long-term memory as a reusable skill, or proactively by pointing it at a GitHub repo so Hermes absorbs an entire knowledge base before you ever ask it to use it.

You'll see the Completion Contract system in action: set a /goal with a verify clause (how Hermes proves it's done), constraints (what it must never do), and boundaries (where it's allowed to act) — and a judge model runs after every turn to decide whether the contract is fulfilled or the loop continues, with a 20-turn budget by default.

You'll run Ministry of Agents (MOA) live — asking one question, having three models answer independently without seeing each other's work, and getting a synthesized response that catches blind spots no single model would catch alone.

You'll discover parallelized sub-agents: instead of tool calls running one after another, Hermes now fans out up to three agents simultaneously — dropping research time from 3 minutes to 15 seconds and cost by 49x, especially when combined with Firecrawl for clean web scraping.

You'll set up Hermes proactivity: connect a Telegram home channel, use /blueprint to schedule tasks in plain English instead of cron syntax, and use /suggestions to have Hermes scan your conversation history and recommend automations it could take off your plate.

You'll close with the Curator — a 7-day background cycle that grades every skill by usage frequency, merges overlapping ones, and removes dead weight automatically — keeping Hermes sharp without any manual maintenance.

#### Who this is for:

- Hermes users who have completed setup, memory, and basic configuration — and are ready to unlock the advanced command layer, autonomous goal execution, and parallelized agent workflows.

- Builders and agency owners who want Hermes running proactively in the background — completing contracts, self-improving overnight, and messaging them with suggestions — rather than waiting passively for the next prompt.
